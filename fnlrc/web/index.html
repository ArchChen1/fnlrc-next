设置

我的 API · DeepSeek

Key 只存在服务端，浏览器拿不到回显。网页版提交需要访问令牌。 翻译只会用到源站没给译文的那些行，并把歌词文本发给 DeepSeek； 选「源站译词」则完全不出网。

Base URL 填 https://api.deepseek.com（不要加 /v1）， 模型名只有 deepseek-flash 与 deepseek-v4-pro 两个。 模型名这类东西会变，以 api-docs.deepseek.com 为准。

音乐库

SMB 共享、只读挂载、容器权限都可能让你「能读不能写」。 先测一次，别等跑了半小时才失败。
它会建一个 fnlrc_write_test.tmp 再删掉。 库内不留东西；但在飞牛上删除会进回收站，那里会多一条同名记录，属正常。

监听文件夹

盯着一个文件夹，新歌下进来就自动补完 —— 不用每次手动点。 适合配合下载器：下载器把歌下到「待整理」文件夹，这边补完歌词并（可选）搬到音乐库。

安全第一：默认只预览不写；只会碰看起来已经下完的文件（下载中、 半截的临时文件会被跳过）；查到歌词之前不会动你的文件。

回填到飞牛（进阶）

    

      飞牛只在歌曲第一次入库时读一次同目录的 .lrc，已经入库的歌
      再怎么写文件都不生效。这个功能直接把歌词写进飞牛的数据库，绕过那个限制
      —— 只改歌词正文、保留 lyric_id，所以歌单、收藏、播放历史都不受影响。
      


      它写的是另一个应用的私有数据库。服务端要显式开启（-e FNLRC_ENABLE_FNOS_WRITE=1）
      才能用，并且每次都会先备份。动手前建议自己再备份一次
      music.db 和 lyric-sqlite/。
    

    

      它的数据在两个地方、而且分属两张表 —— 主库的
      @appdata 里是歌词索引（lyric 表，
      没有正文），正文在存储池 @appmeta 的分片里
      （lyric_content 表）。
      两处都要挂进容器，只挂一处会找不到另一半。
    

    

      
      
    

    
    

      勾上之后，「库里一行歌词都没有」的歌也会被填上（真机实测应用能立刻认）。
      不勾则只改已有歌词的正文。
      

      已有歌词的歌永远不会被新建：偏好表以 lyric_id 为键，
      插一条新行而不动偏好，应用仍然显示旧那版 —— 你会以为没生效。
