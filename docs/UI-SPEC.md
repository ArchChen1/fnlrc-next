# 界面规格（UI Spec）

> 这份是**给改界面的人看的规格**。想学怎么用，看 [GUIDE.md](GUIDE.md)。

> 目标用户里有大量**不懂技术的人**，所以界面原则只有一条：**一个 Tab 里只有一个明显的下一步**。
> 桌面端与网页端共用这一份 UI（单页，无构建步骤）。

---

## 一、设计原则

1. **一 Tab 一事**：选库 → 概览 → 补完 → 进度 → 报告，五步分在五个 Tab 里、不混排
2. **默认安全**：默认勾选「预览模式（先不写入）」，让用户先看到会发生什么
3. **默认零配置**：不用填任何 key，打开就能跑
4. **永不静默失败**：任何失败都要有中文人话说明 + 可操作建议
5. **可疑项单独露出**：不把「可能匹配错了」混在成功里，单独一栏让人确认
6. **长任务可离开**：进度 Tab 可以关掉再回来（任务在后端跑）
7. **随便点**：Tab 不因为「还没到那一步」就禁用，只置灰提示 —— 用户能先预览整个流程

---

## 二、页面结构（单页 + 五个 Tab）

**M5 起不再整屏滚动吸附**：一个页面、五个面板，点 Tab 切换。
不管内容多少都按自然高度排版，**页面整体滚动**，不再把表格/日志压进一屏高。

| Tab | 内容 | 什么时候能点 |
|---|---|---|
| **选库** | 输入/浏览音乐库路径 + 扫描 | 始终 |
| **概览** | 扫描统计、按目录分布 | 扫描完成后 |
| **补完** | 预览判定 + 选项 + 开始 | 扫描完成后 |
| **进度** | 实时日志 + 进度条 | 有任务时 |
| **报告** | 结果列表 + 筛选 + 导出/回滚 | 有报告时 |

未满足条件的 Tab 用 `data-locked="true"` **置灰但仍可点**，点了弹一句提示告诉用户缺哪一步
（`tab.locked_scan` / `tab.locked_run` / `tab.locked_report`）。

### ① 选库

```
  音乐库路径
  ┌──────────────────────────────────────────────┬──────────┐
  │ \\192.168.0.2\音乐                            │  浏览…   │
  └──────────────────────────────────────────────┴──────────┘
  · 支持本地文件夹、SMB 共享（\\NAS\音乐）、映射盘符
  · 网页版支持挂载进容器的路径（如 /music）

  [ 扫描音乐库 ]        ← 主按钮，只有一个
```

- 「浏览」在桌面端弹**原生文件夹对话框**；网页端弹目录浏览弹窗（`/api/fs`）
- 记住上次路径（`localStorage`），下次打开自动填好
- 空状态文案：*"选一个包含音乐文件的文件夹。不确定选哪个？在飞牛里看到的那个音乐目录就是它。"*

### ③ 补完预览（**默认不开写入**）

```
  这些是即将执行的操作（还没有写入任何文件）
  ┌────────────────────────────────────────────────────────────┐
  │ ☑ 预览模式（不写入，只生成到 fnlrc_out/）                    │
  │ ☐ 强制重做已有双语歌词                                       │
  │ 翻译后端： ( ● ) 源站译词（免配置）  ( ) 我的 API  ( ) 不翻译 │
  └────────────────────────────────────────────────────────────┘

  判定分布：  会补成双语 246 │ 会跳过 211 │ 需人工确认 3 │ 纯音乐 53

  ┌────────┬────────────────────────────┬──────────────┬────────┐
  │ 判定    │ 文件                        │ 原因          │ 详情   │
  ├────────┼────────────────────────────┼──────────────┼────────┤
  │ ✓ 双语  │ 日语\残酷な天使のテーゼ.flac │ 无外挂歌词    │ 预览 ▸ │
  │ ✓ 双语  │ 英语\Teeth.flac             │ 外文单语→保留 │ 预览 ▸ │
  │         │                             │ 本地轴只补译文 │        │
  │ ⊘ 跳过  │ 中文\书香年华.flac           │ 中文单语无需双 │ ─     │
  │ ⊘ 跳过  │ 纯音乐\…Waltz No. 2.flac     │ 纯音乐(zxx)   │ ─     │
  │ 🔴 人工 │ 中文\…莫斯科郊外的晚上.flac  │ 外文歌抓到中文版│ 查看 ▸ │
  └────────┴────────────────────────────┴──────────────┴────────┘

  [      开始补完（520 首，预计约 75 分钟）      ]
```

- 「预览 ▸」弹出该曲的**双语 LRC 前 12 行** + **飞牛双行判定**（并行组/比例/是否通过）
- 数量少于 200 首时可选择「只处理前 N 首」先试水
- 外文单语那条的**原因文案必须说清是"保留本地时间轴"还是"重抓"** —— 两者的结果
  对用户差别很大（前者原文行与时间戳一个都没动），不能都写成"补成双语"。
  文案随「设置 → 保留本地时间轴」的开关变化
- 乱码曲目的原因要把**形态**写出来（如 `mojibake:gbk-as-big5`），不能只说"重来过" ——
  乱码的根因常在源头，重刮是无用动作，用户该做的是提供正确原文

## 三、设置页

| 项 | 默认 | 说明 |
|---|---|---|
| 备份旧歌词 | ✅ 开 | 替换前存 `.bak`，可回滚 |
| **保留本地时间轴** | ✅ 开 | 外文单语歌词沿用**用户文件里**的时间轴与断句，只按相同时间戳插译文行。取消勾选 = 按源站整份重写（`--rebuild-local`） |
| 默认预览模式 | ✅ 开 | 首次使用更安全，熟练后可关 |
| 翻译后端 | 源站译词 | 三选一：源站译词 / 我的 API / 不翻译 |
| 我的 API | 空 | **只做 DeepSeek 一家**：Base URL `https://api.deepseek.com`（不带 `/v1`）+ 模型 `deepseek-flash` + Key，带「测试连接」 |
| 测试写入 | — | 调 `/api/write-test` 验证目标目录可写（SMB 只读挂载/容器权限会在这里现形）。**会建一个 `fnlrc_write_test.tmp` 再删掉** —— 库内不留东西，但在开了回收站的系统上（飞牛就是）回收站会多一条记录，说明里要写清 |
| **监听文件夹** | 关 | 分组：监听目录（输入框）、补完后（留原地/复制到音乐库/移动到音乐库）、音乐库目录、直接写入旁挂 `.lrc`（勾选框）、静默秒数、轮询间隔、随服务自动启动（勾选框）；按钮「保存监听设置」+「开始监听/停止监听」+ 状态文案 + 实时事件日志（SSE，`#watchLog`）。**默认不勾「直接写入」**（先预览更安全）；`POST /api/watch/start` 读已保存配置，所以「开始监听」会先把面板值存一次 |
| 主库目录 / 歌词分片目录 | 空 | 「回填到飞牛」的两个路径输入框。**两处都要填**（主库在系统盘 `@appdata`、歌词分片在存储池 `@appmeta`），只挂一处探测就报"没找到"。旁边三个按钮：① 检测结构（只读）② 预览差异（只读）③ 执行回填（默认**点不动**） |
| 单曲超时 | 25 秒 | 网络差可调大 |
| 翻译时限 | 180 秒 | 与抓取分开：远端 API 翻一首长歌要分好几个块，共用 25 秒会把稍长的歌判超时 |
| 源站节流 | 网易云 0.35s / LRCLIB 1.2s | 高级项，鼠标悬停解释「调小可能被限流」 |
| 日志目录 | 自动 | 出问题时报错页会直接给出路径 |

## 四、状态与文案约定

| 状态 | 图标 | 颜色 | 一句话文案 |
|---|---|---|---|
| `written` | ✓ | 绿 | 双语 N 组 |
| `written_keep_local` | ✓ | 绿 | 双语·留本地轴（沿用你文件的时间轴，只补了译文） |
| `written_mono` | ⚠ | 黄 | 已写单语（没有可用译文，或译词覆盖不足） |
| `skipped_existing` | ⊘ | 灰 | 已是双语 / 中文单语，跳过 |
| `skip_instrumental` | ⊘ | 灰 | 纯音乐，无需歌词 |
| `no_lyrics` | ⚠ | 黄 | 两个源都没有歌词（可重试） |
| `timeout` | ⚠ | 黄 | 抓取超时，可重试 |
| `lang_mismatch` | 🔴 | 红 | 抓到的像是中文翻唱版歌词，需你确认 |
| `validate_failed` | 🔴 | 红 | 双语合成未通过飞牛规则。**运行期已不再产生**：译词覆盖不足时会退回 `written_mono` 而不是什么都不写。保留该状态只为兼容旧报告 |
| `write_failed` | 🔴 | 红 | 写入失败（权限/文件被占用） |
| `error` | 🔴 | 红 | 出错了（附日志路径） |

**文案纪律**：不出现技术黑话。`parallelGroupId` → 「双行分组」；`status=lang_mismatch` → 「歌词语言对不上，怕是翻唱版」。

## 五、视觉与实现约定

### 视觉风格：`single-page-tabs`（StyleKit 延续）

整站按这一份风格规范实现，**不要混入别的风格**。M5 只改了布局（整屏吸附 → Tab），
视觉 token 一个都没动：

| token | 取值 |
|---|---|
| 底色 / 文字 | `bg-black` / `text-white` |
| 描边 | `border-white/20`（浅一档用 `white/10`） |
| 圆角 | 按钮与标签一律 `rounded-full` |
| 层次 | **全靠色块与渐变，全站零阴影** |
| Hero | `text-5xl md:text-7xl lg:text-8xl` + `font-bold tracking-tight` |
| 正文 | `text-lg md:text-xl lg:text-2xl` |
| 容器内边距 | `px-6 md:px-8 lg:px-12` |
| 卡片内边距 | `p-8 md:p-12` |
| 主按钮 | `bg-white text-black` → `hover:bg-white/90` |
| 次按钮 | `border-2 border-white` |
| 渐变卡片 | `from-indigo-600 to-purple-700`、`from-cyan-600 to-blue-600` |
| 输入框 | `border-b border-white/30` + `placeholder:text-white/50` + `focus:outline-none` |

**禁用项**（CI 门禁，`fnlrc/web/` 下必须零命中）：

```bash
grep -rE "shadow-(sm|md|lg|xl)|border-gray|text-zinc" fnlrc/web/
```

### 布局：页面自然滚动，不做整屏吸附

- 结构是 `.app > .topbar + main.panels > section.panel × 5`，每个面板按**内容自然高度**排版
- **不再有 `height:100dvh` / `scroll-snap` / 右侧导航点** —— 那是 M5 之前的做法，
  手机上会出现「地址栏一收就跳、内容稍长就内部再滚动」的双层滚动
- `section.panel[hidden] { display:none }` 切 Tab，键盘左右箭头切换
- 表格 / 日志在桌面用 `max-height` 限量并可内部滚动；**窄屏（<768px）取消内部滚动**，
  交给整页滚动，避免「滚动套滚动」
- 刷新后回到上次所在 Tab（`localStorage["fnlrc_tab"]`）

### 响应式

| 断点 | 布局 |
|---|---|
| `≥768px` | 顶栏中间横排 Tab 条；内容居中 `max-width:64rem` |
| `<768px` | 顶栏 Tab 隐藏；**底部固定一行纯文字 Tab，5 项等分**；`padding-bottom: env(safe-area-inset-bottom)`；`.panels` 预留底部内边距 |
| `pointer:coarse` | 按桌面布局，但按钮 / Tab 同样 `min-height:44px` |

### 触控与可发现性

- 手机所有可点元素 **≥44×44px**（按钮 `min-height:44px`，底部 Tab 52px）
- 输入框在手机上 `font-size:16px`，防止 iOS 聚焦自动放大
- 内容层用错落的 delay（`d0 / d75 / d150 / d225 / d300`），**不能所有元素同 delay**
- 每个面板保留 `.glow` 径向渐变背景，轻微 hover 放大
- 顶栏提供「报告 ⤓」快速跳转（与点「报告」Tab 同一路径，锁定态给提示）
- 键盘 ← → 切 Tab；弹层打开或在输入框里时不抢键
- 提示条 `toast` 设 `pointer-events:none`，手机上不挡住底部 Tab

### 文件组织

```
fnlrc/web/
├── index.html          结构（唯一需要服务端参与的地方：令牌占位符）
├── styles.css          设计 token + 组件（:root 变量与上面的 token 一一对应）
└── js/
    ├── state.js        全局状态 + 文案表（零依赖，避免循环引用）
    ├── core.js         DOM 工具 + 带令牌的 fetch 封装
    ├── fsbrowser.js    网页版目录浏览
    ├── screens.js      五个 Tab 的渲染与交互（initTabs/go/requestTab）
    ├── panels.js       设置 / 历史 / 令牌闸门（含监听文件夹设置与 SSE 事件日志）
    ├── wizard.js       首次使用引导（欢迎 → 令牌 → 选库，ADR-018）
    └── main.js         装配与启动
```

- **原生 ES module，仍然零构建步骤、无 node_modules** —— 桌面版要能离线跑，
  所以也不用 Tailwind CDN，而是把它的 token 用原生 CSS 等价实现
- 打开面板时三者各占一个 overlay/dialog，**互不覆盖彼此的 DOM**
  （早先塞进同一个 sheet，结果打开「历史」会把设置表单整块替换掉）
- 状态管理：一个 `state` 对象 + 渲染函数；不引入框架
- 进度：`EventSource('/api/jobs/{id}/events')`；断线自动重连并拉 `/api/jobs/{id}` 快照
- 国际化：文案集中在 `js/state.js` 的常量里，为将来 i18n 留口

## 六、可访问性 & 边界情况

- 全键盘可用：Tab 顺序 = 阅读顺序；主按钮回车可触发
- 中文路径/emoji/日文一律原样显示（UTF-8 全链路）
- 超长文件名中间省略（`…`），悬停显示完整路径
- 库为空 → *"这个文件夹里没找到音频文件。支持 mp3/flac/m4a/wav/ogg/ape 等。"*
- 路径不存在/无权限 → *"打不开这个路径。如果它在 NAS 上，先在系统里映射好，或检查权限。"*
- 服务未就绪 → 加载页骨架屏 + "正在启动本地服务…"
- 任务进行中用户点了「重新扫描」→ 提示"任务正在运行，完成后才能重新扫描"
