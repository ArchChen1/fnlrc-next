# 界面怎么用

桌面版和网页版是**同一份界面**，所以这一篇两边都适用。区别只有两处，遇到时会单独标出来。

界面分成**五个标签页**：选库 / 概览 / 补完 / 进度 / 报告。点哪个看哪个，不用从上往下滚。
电脑上标签在顶上一排；手机上在**屏幕最底下**一排（拇指够得到的地方）。
刷新页面会回到你上次停留的那一个。键盘的 ← → 也能换。

---

## 第一个标签：选库

打开之后就是这个。

**在「音乐库路径」里填你的音乐文件夹**。填什么：

- Windows 本地盘：`D:\音乐`
- NAS 共享：`\\192.168.0.2\音乐`（就是你在资源管理器里能打开的那个路径）
- 映射盘符：`Z:\`
- 网页版跑在 NAS 上的话：填容器里的路径，通常是 `/music`

不确定填哪个？在飞牛的文件管理器里翻到你那个音乐目录，看它的路径是什么，照抄。

点「浏览…」可以挑。桌面版弹的是系统原生的文件夹对话框；网页版弹的是程序自己的目录浏览框，点目录进去、点「就用这个目录」确认。

填过一次它会记住，下次打开自动填好。

**然后点「扫描音乐库」。**

> ⚠️ 这里要留意：填完之后**先确认路径对不对**。填错了要么扫不到东西（提示「这个文件夹里没找到音频文件」），要么扫到一堆不该处理的文件。扫描这一步它只读不写，所以放心点。

---

## 第二个标签：概览

扫完自动跳到这里。它告诉你库里现在什么状况。

上面四个数字：

| | 意思 |
|---|---|
| 音频总数 | 扫到多少个音频文件 |
| 已有双语 | 已经有合规双语 `.lrc` 的，这些会被跳过 |
| 需要补完 | 没有歌词、歌词乱码、外文单语——这些是要处理的 |
| 纯音乐跳过 | `language=zxx` 标签的，不需要歌词 |

下面按目录列出来，你能看出哪个目录缺得最多。

> ⚠️ 这里要留意：**「需要补完」这个数字对不对**。如果你知道库里日语歌有 166 首，但这里只显示几十首，多半是扫描没扫全（路径层级不对、或者有权限问题）。数字差得离谱就别往下走，先查路径。
>
> 另外注意「已有双语」那一栏——**这些歌不会被碰**。如果你发现某首歌明明双语是错的却没被列进「需要补完」，原因就在这：程序认为它已经合规了，跳过。

确认没问题，点「查看补完预览」。

## 第三个标签：补完

这个标签是**最重要的一个**，因为在这里决定要做什么、以及会不会真的写。

### 三个选项

**☑ 预览模式（默认勾选）**

勾着的时候，所有结果只生成到一个单独的目录（`fnlrc_out/`），**你的音乐库一个文件都不会动**。

第一次用建议就这么跑，跑完去那个目录里翻几个文件看看效果。

确认满意了，**取消勾选再跑一次**，才会真写到音乐旁边。

**☐ 强制重做已有双语歌词（默认不勾）**

不勾的时候，已经是合规双语的歌会被跳过。

勾上之后，这些歌也会重新做一遍。什么时候用：你觉得现有的双语歌词质量不好，想全部换成新刮的。**这个操作会覆盖已有文件**（虽然会备份成 `.bak`）。

> 注意：勾了「强制重做」之后，本地那份外文单语歌词的时间轴也不会被沿用了 —— 强制重做的意思就是从源站整份重来。

**外文单语歌词怎么处理（在设置里，默认保留本地时间轴）**

有一类歌你会特别在意：**已经有 `.lrc`，是外文单语，而且那个时间轴是你自己一句一句对过的**。

默认行为是**保留它**：解析你那份文件的时间轴和断句，只把网上的译文按相同时间戳插进去，原文行一个字不动。这样你精修过的轴不会被换掉。

如果拼出来的结果过不了飞牛的双行规则（网上给的译文覆盖太少），程序会**自动退回重抓**，并在报告里写明原因 —— 不会硬塞给你一个不成对的文件。

**想关掉它**：右上角「设置 ⚙」→「其它」→ 取消勾选「外文单语歌词：保留本地时间轴，只把译文插进去」。关掉之后就一律按源站整份重写，也就是老行为。

**翻译后端（三选一）**

| 选项 | 什么时候选 |
|---|---|
| **源站译词**（默认） | 一般就选这个。用网易云自带的中文翻译，不花钱、不往外发歌词。缺点是有少数歌源站没给翻译，那些歌会写成单语 |
| **AI 翻译** | 你配了 OpenAI 兼容端点（如 DeepSeek）的 key。源站没给翻译的行会交给它翻。**歌词文本会发出去** |
| **不翻译** | 只修乱码、规范格式，不生成译文 |

配 key 的地方在右上角「设置 ⚙」里。

### 判定分布

右边那个紫色的块会告诉你：有多少首会新建、多少首会补成双语、多少首会跳过、多少首需要你人工确认。

### 下面的表格

每一行是一首歌，告诉你**准备怎么处理它**以及**为什么**：

- `会新建` —— 现在没歌词，准备写一份
- `会补成双语` —— 有外文单语歌词，准备换成双语的
- `会重做` —— 现有 `.lrc` 是乱码或空的，准备重来
- `会跳过` —— 已经是双语的，或者是中文单语，不用动

> ⚠️ 这里要留意三件事：
>
> 1. **概览里的数字和这个表格对得上吗**。比如概览说「需要补完 309」，这里列出来的行数应该差不多。
> 2. **「原因」那一列里有「外文单语歌词 → 补成双语」的歌**——这些歌原本的 `.lrc` 会被**整份替换掉**。如果里面有你不想丢的，现在就得把它挑出来（取消勾选预览模式之前先把它移走，或者先备份）。
> 3. **有内嵌歌词的歌**会被标出来。这些歌写了外挂 `.lrc` 也没用，飞牛读的是内嵌那版。可以先不管它们，也可以自己拿别的工具把内嵌清掉再回来处理。

确认之后点「开始补完」。

## 第四个标签：进度

进度条和一堆实时数字。这里不用管，看就行。

上面那个进度条会一直涨。下面几块数字分别是有多少已经写入、多少写成单语、多少跳过、多少找不到歌词、多少超时、多少等你确认、多少失败。

再下面是实时日志，一行一首歌：

```
✓ 双语       日语\残酷な天使のテーゼ.flac 并行组=48 比例=1.0 ← 高橋洋子 - 残酷な天使のテーゼ (8.0)  0.7s
⚠ 无歌词     小语种\Белая кошка.flac  两个源都没有歌词  16.4s
⊘ 纯音乐     纯音乐\Waltz No. 2.flac  0.0s
```

箭头 `←` 后面就是它**实际匹配到了哪一首**。这是判断有没有匹配错的关键信息，值得扫一眼。

**关于时间**：一首先后要等网易云搜索、取歌词、可能还有 LRCLIB 兜底、再可能翻译。520 首的库实测跑完大约 70 分钟，绝大部分时间花在等在线接口上。喝杯咖啡去。

> ⚠️ 这里要留意：
>
> **「停止」是优雅停止**——当前这首处理完就停，已经写进去的文件保留。不是一键撤销。想撤销去报告页，或者用 `.bak`。
>
> 网页版关掉浏览器没关系，任务在服务端继续跑。重新打开页面点「历史」还能看到。

## 第五个标签：报告

跑完了自动跳这里。

最上面一行是汇总：写入多少、单语多少、跳过多少、无歌词多少、超时多少、待人工多少、失败多少。

下面可以按状态筛选。表格每行的列：

- **状态**：✓ 双语 / ✓ 双语·留本地轴 / ⚠ 单语 / ⚠ 无歌词 / ⚠ 超时 / 🔴 待人工 / 🔴 失败
- **文件**：相对路径
- **匹配到**：**实际配到了哪一首歌**——这一列最值得核对
- **来源**：netease / lrclib
- **并行组 / 比例**：飞牛双行判定的结果。比例 1.0 就是每一行都成对了

「**✓ 双语·留本地轴**」是单独一档，因为它和普通「✓ 双语」不一样：那一首的译文是按**你本地文件的时间轴**插进去的，原文行和时间戳都没动。两者在汇总里都算「已写入」，但要区分的话看这一列。

底部三个按钮：导出 CSV、再来一次。

> ⚠️ 这里要留意：
>
> 1. **「待人工确认」永远排最上面**。这些是「外文歌却抓到中文歌词」的歌，很可能是匹配到了中文翻唱版，程序故意不写。点进去看文件，确认是不是你要的版本。
> 2. **「匹配到」这一列有可疑的**就记下来。比如一首日语歌配到了明显不认识的艺人，那多半错了。
> 3. **导出 CSV** 之后可以用 Excel 排序筛选，比在页面上翻方便。
> 4. 右下角那句话是认真的：**飞牛不会重读已入库歌曲的 `.lrc`**。新歌按正确顺序（先补完再入库）处理的才会生效；已经在库里的，看 [FNOS-SIDECAR.md](FNOS-SIDECAR.md)。

## 设置面板（右上角 ⚙）

点开是一个盖在上面的小窗口，关掉不影响正在跑的任务。分六组：
界面语言 / AI 翻译 / 音乐库 / 监听文件夹 / 其它 / 回填到飞牛。

**每一项到底是干什么的、什么时候该动，写在 [使用教程.md](使用教程.md) 的「设置」一节。**
这里只说最常用的三件事。

### 填 API key（可选）

默认用「源站译词」，完全不出网，**这一组空着也能跑**。

要用 DeepSeek 补翻源站没给译文的行时，填 API Key，点「测试连接」。
Base URL 和模型名默认已填好，通常不用动。失败会直接说是 key 无效、余额不足、
模型名不对还是网络不通。

key 只存在服务端，页面上永远拿不到回显；留空就是不改。

### 测试写入权限

**部署完、换过挂载、改过权限之后，第一件事就点这个。**

它在音乐库目录里建一个临时文件再删掉。SMB 共享、只读挂载、容器权限都可能让你
「能读不能写」，早发现比跑到一半报一片失败强。

### 两个默认开着的开关（在「其它」里）

- **替换旧歌词前备份 `.lrc.bak`** —— 关掉就没有后悔药了，建议一直开着。
- **外文单语歌词：保留本地时间轴，只把译文插进去** —— 沿用你文件里的时间轴和断句，
  只补译文行。手工精修过时间轴的人需要它；取消勾选 = 一律按源站整份重写
  （命令行对应 `--rebuild-local`）。

### 界面语言

最上面的下拉框，只有「中文」和「English」。选完**整页立刻变**，不用刷新，
下次打开还是你上次选的那个。

它**不改**你库里的文件名、目录名和 `.lrc` 内容；也**不翻译报告里的「原因」列**
（比如「两个源都没有歌词」）—— 那是数据，跟着歌走，不跟界面语言走。

> 英文文案是机器翻的，够看懂但不如中文顺。拿不准就切回中文对照。

## 网页版专有的那个门

网页版不是从本机打开的，所以**不会自动带上访问令牌**。第一眼看到的是这个：

```
需要访问令牌
这个服务不是从本机打开的，所以不会自动带上令牌。
在服务器上执行下面这条命令拿到它：
  docker logs fnlrc 2>&1 | grep -i token
```

把令牌粘进去，点进入。它会存在浏览器里，下次不用再填。

如果提示「令牌不对」，去服务器上重新取一次。如果确认令牌没错还是进不去，可能是服务重启后令牌变了。

**从本机打开**（`http://127.0.0.1:8080`）不会看到这个门——它会自动把令牌注进去，因为那本来就是你自己那台机器。

> ⚠️ 令牌和 API key 一样重要。只凭它就能触发写入和回滚。别截图发出去，别提交到仓库。怀疑泄露：
>
> ```bash
> docker exec fnlrc python -m fnlrc token --rotate
> ```

## 顶栏那几个按钮

- **报告 ⤓** —— 直接跳到「报告」那个标签。没跑过任务时会提示你先跑一次。
- **设置 ⚙** —— 上面说的那个面板。
- **历史** —— 以前跑过的任务。可以点进去看当时的报告，换个筛选看看。重启程序之后历史还在（存在数据目录里）。

---

## 标签变成淡色是什么意思

报告还没出来的时候，「进度」和「报告」这两个标签会变淡 —— **但照样能点**。
点一下会弹一句提示，告诉你还差哪一步（比如「还没有跑过任务，先点补完里的开始」）。
这是故意的：你现在就能看到后面长什么样，不用先把前面填完。

---

## 一个标签里只能做一件事

这是刻意的设计。五个标签对应五步，每一个里只有一个明显的下一步按钮。别跳步——尤其别跳过「补完」里的预览直接开始写。

如果你熟悉了想快一点，命令行可以一步到位：

```bash
python -m fnlrc run --root "/vol2/1000/音乐" --write
```

但**第一次用，走界面**。看一遍它准备做什么，比事后回滚省事得多。
