## 设置

点右上角的 **设置 ⚙** 打开。设置是个盖在上面的小窗口，关掉不影响正在跑的任务。

设置分六组：**界面语言 / 我的 API / 音乐库 / 监听文件夹 / 其它 / 回填到飞牛**。
界面上每组只留一句话，下面把每一项到底干什么、什么时候该动，写清楚。

### 界面语言

一个下拉框，只有「中文」和「English」。

- 选完**整页立刻变**，不用刷新：按钮、表头、状态文字、报告里那几列都跟着换。
- 下次打开还是上次选的那个（记在这台浏览器里）。
- **不影响你的文件**：音乐库目录名、文件名、`.lrc` 内容一个字都不动。
- **不翻译数据**：报告里灰色的「原因」列（比如「两个源都没有歌词」）保持中文，
  因为它描述的是这首歌当时的实际情况，跟着歌走，不跟界面语言走。
  这样你把报告贴给别人时，别人搜得到同样的说法。
- 导出的 CSV 里的状态值（`written_mono`、`lang_mismatch` …）永远是英文枚举，
  换语言不会让昨天导出的表和今天的不一样。

> 英文是机器翻的，够看懂但不如中文顺。哪句拿不准，切回中文对照一下。

### 我的 API · DeepSeek

只有你把「翻译后端」选成 **我的 API** 时才会用到这一组。选「源站译词」（默认）完全不出网，
这组空着也没关系。

| 项 | 填什么 |
|---|---|
| API Key | DeepSeek 控制台里那串 `sk-...` |
| Base URL | `https://api.deepseek.com`（已经填好，通常不用动） |
| 模型名 | `deepseek-flash` 或 `deepseek-v4-pro` |

**Base URL 不要加 `/v1`**。加了有时候也能通，但官方文档给的是不带的，照文档来最省事。

**模型名会变**。上面这两个是写文档时文档里有的；哪天报「模型不存在」，
先去 `api-docs.deepseek.com` 看一眼现在的名字，再填回来。

填完点 **测试连接**。它会发一条最短的请求验证，失败会直接说清是哪种：
key 无效、余额不足、模型名不对、还是网络不通。

**Key 只存在服务端**，页面上永远拿不到回显。填过一次之后，这里显示「已配置：`sk-123***cdef`」，
**留空就是不改**。如果服务端是用环境变量 `FNLRC_REMOTE_API_KEY` 启动的，这一栏会变成只读。

**什么时候会花钱**：只有「源站没给译文的那几行」才会被送去翻译，
已经带上中文译词的歌一行都不会发。选「源站译词」则完全不出网。

### 音乐库

**测试写入权限** —— 点一下，它在你的音乐库目录里建一个 `fnlrc_write_test.tmp` 再删掉。

部署完、换过挂载、改过权限之后，**第一件事就该点这个**。SMB 共享、只读挂载、
容器用户不对，都可能让你「能读不能写」，等跑了半小时才在报告里看到一片失败，很亏。

> 库里不会留下东西。但在飞牛上删除会进回收站，那里会多一条同名记录 —— 这是正常的。

**重置访问令牌** —— 只对网页版有意义。令牌只能在服务端重置
（`fnlrc token --rotate`），页面上这个按钮只是告诉你命令。

### 监听文件夹

盯着一个目录，新歌下进来就自动补完，不用每次手动点。
典型用法：下载器把歌下到「待整理」目录，这边补完歌词，再（可选）搬到音乐库。

**安全设计**：

- 默认**只预览不写**，想真写要勾「直接写入旁挂 `.lrc`」。
- 只碰**看起来已经下完**的文件：正在下载的、`.part` / `.!qB` 这类临时文件会被跳过；
  再配合「静默几秒」——文件安静够久才动手，防止半截文件被误处理。
- **查到歌词之前不动你的文件**。找不到词就留在原地，等下次。

| 项 | 说明 |
|---|---|
| 监听目录 | 要盯的文件夹（容器里填容器路径，如 `/music/inbox`） |
| 补完后 | 留在原地 / 复制到音乐库 / 移动到音乐库 |
| 音乐库目录 | 上面选了复制或移动时，搬到哪儿 |
| 直接写入旁挂 `.lrc` | 不勾 = 只把结果预览到输出目录，不改你的库 |
| 静默几秒后才处理 | 防止半截文件；下载速度慢的网络盘建议调大 |
| 轮询间隔秒 | 多久看一次目录。太密没必要，默认够用 |
| 服务启动时自动开始监听 | 勾上之后开服务就自己盯，不用每次手动点 |

改完记得先 **保存监听设置**，再点 **开始监听**（或停止）。
下面的黑色窗口是实时日志，新文件进来、处理完、搬到哪儿，都在这里滚。

> 只监听一个目录；监听目录和音乐库目录**不能是同一个**，否则搬来搬去会打架。

### 其它

**替换旧歌词前备份 `.lrc.bak`** —— 默认开，建议一直开着。
关掉之后覆盖就没有后悔药了，回滚也只能回到上一次的备份。

**外文单语歌词：保留本地时间轴，只把译文插进去** —— 默认开。

你那首歌已经有单语 `.lrc` 时，工具**沿用你文件里的时间轴和断句**，
只按相同时间戳补译文行，原文一行都不改。手工精修过时间轴的人特别需要它。

- 对齐结果过不了飞牛双行规则时会自动退回「重抓」，并在报告里说明。
- 取消勾选 = 一律按源站整份重写（老行为）。命令行对应 `--rebuild-local`。

### 回填到飞牛（进阶）

**这一组只用在你已经在飞牛里建好库、并且想让老歌也立刻显示双语的时候。**
普通新歌不用碰它：歌词跟着文件一起入库就行。

为什么需要它：飞牛只在歌曲**第一次入库**时读一次同目录的 `.lrc`，
已经入库的歌再怎么写文件都不生效。这个功能直接把歌词写进飞牛的数据库，
绕过那个限制 —— 只改歌词正文、保留 `lyric_id`，
所以**歌单、收藏、播放历史都不受影响**。

**三件必须先知道的事**：

1. 它写的是**另一个应用的私有数据库**。服务端要显式开启
   （`-e FNLRC_ENABLE_FNOS_WRITE=1`）才可用，并且**每次都会先备份**。
   动手前建议自己再备份一次 `music.db` 和 `lyric-sqlite/`。
2. 数据分在**两个地方、两张表**：主库 `@appdata` 里是歌词**索引**
   （`lyric` 表，没有正文），正文在存储池 `@appmeta` 的分片里（`lyric_content` 表）。
   **两处都要挂进容器**，只挂一处会找不到另一半。
3. **已有歌词的歌永远不会被新建**。偏好表以 `lyric_id` 为键，
   插一条新行而不同步偏好，应用仍然显示旧那版 —— 你会以为没生效。

**怎么用**：按顺序三步，每一步都会先把结果打出来给你看。

1. **① 检测结构** —— 看看两个目录能不能读到、表对不对。不对会直接说缺什么。
2. **② 预览差异** —— 比对「库里的歌词」和「你刚补完的 `.lrc`」，
   告诉你打算改多少首、哪些是新建。**这一步不改任何东西。**
3. **③ 执行回填** —— 确认数字没问题再点。会再问你一次，写之前自动备份。

那个「给没有歌词的歌新建歌词行」的勾：勾上，「库里一行歌词都没有」的歌也会被填上
（真机实测应用能立刻认）；不勾则只改已有歌词的正文。
**勾选状态一改，之前那次预览就作废了**，要重新点「② 预览差异」，否则会因数字对不上被拦下。

写完之后回飞牛刷新一下，歌还是那首歌，歌词应该已经是双行的了。
